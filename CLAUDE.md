# LAN Chat — заметки для Claude

## Экономия токенов

- Не выводить содержимое файлов после Write/Edit «для проверки» — инструмент уже
  подтверждает успех, повторное чтение не нужно.
- Не цитировать длинные блоки кода в ответе пользователю, если можно сослаться
  на `файл:строка`. Код уже виден в diff/редакторе.
- Вывод диагностических команд (build, тесты, grep) держать коротким:
  `tail`/`head`/фильтры вместо полного лога, если не идёт расследование ошибки.
- В ответах пользователю — по сути и кратко: что сделано, что проверено, что дальше.
  Без пересказа промежуточных шагов и без повторения того, что уже видно из diff.
- Временные/диагностические файлы (тестовые стенды, скрипты для разовой проверки)
  держать в scratchpad-папке сессии, не копить в репозитории.

## Сборка — нужны все архитектуры

Публикация всегда собирает **обе** версии: x64 и x86 (`LanChat-64bit.exe` и
`LanChat-32bit.exe`). Не ограничиваться только x64 «по умолчанию» — пользователь
явно просил, что нужны обе, т.к. часть машин в сети может быть 32-битной.

- `publish.ps1` без аргументов уже собирает обе (`-Arch both` — значение по умолчанию).
  Если меняешь скрипт — не меняй дефолт на один вариант.
- Windows 7 **не поддерживается** в принципе — не разрядностью, а тем, что рантайм
  (`net10.0-windows`) с .NET 7+ вообще не ставится на Win7/8/8.1, только Win10 1607+.
  Если когда-нибудь всплывёт реальная нужда в Win7 — это отдельная ветка на
  .NET Framework 4.8, а не флаг publish. Пользователь уже решил: Win7 не нужен,
  ограничиваемся Win10/11 x64+x86.
